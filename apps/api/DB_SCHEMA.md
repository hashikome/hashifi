# WiFi Billing MySQL Schema

This backend uses Drizzle ORM with MySQL. The schema is in `src/db/schema.ts`, and the database client is exported from `src/db/index.ts`.

## Setup

1. Copy `.env.example` to `.env`.
2. Set `DATABASE_URL` to your MySQL connection string.
3. Install backend dependencies.
4. Generate migrations with `npm run db:generate`.
5. Apply migrations with `pnpm db:migrate`.

If the database was previously synced with `db:push`, the migrate script detects that and baselines the initial migration before applying newer ones.

For early local development, `npm run db:push` can sync the schema directly to MySQL, but migrations are better once the schema starts stabilizing.

## Core Areas

### Admin And Auth

- `admin_users`: admins and retailers who manage the system.
- `admin_otp_codes`: hashed OTP login codes for admin authentication.
- `admin_sessions`: 3-day server-side admin sessions keyed by hashed cookie tokens.
- `admin_preferences`: per-admin theme and notification settings.
- `audit_logs`: admin actions against users, vouchers, routers, packages, settings, and other entities.

### Network Topology

- `venues`: malls, cafes, buildings, schools, or any place where WiFi is sold.
- `routers`: MikroTik/router records, API credentials, hotspot/PPPoE settings, and live router status.

### Access Products

- `packages`: sellable internet plans with duration, speed, data limit, device limit, and TSH price.

### Customers, Vouchers, And Payments

- `wifi_customers`: customer/device identity by phone, MAC address, email, and device details.
- `voucher_batches`: bulk voucher generation metadata.
- `vouchers`: individual voucher codes, lifecycle status, limits, usage, and expiry.
- `payments`: M-Pesa, cash, card, and manual payment records linked to customers, packages, vouchers, and venues.

### Sessions And Analytics

- `wifi_sessions`: live and historical customer sessions from routers.
- `session_usage_samples`: periodic traffic/speed/signal snapshots for a session.
- `daily_usage_stats`: daily aggregate usage and revenue by venue/package.

### Portal Customization

- `portal_settings`: one customizable captive portal and voucher template per venue, including logo, colors, message, voucher labels, package visibility, M-Pesa visibility, phone collection, and terms requirement.

## Design Notes

- Primary keys are `varchar(36)` UUIDs generated by the Drizzle runtime.
- Join tables use UUID primary keys plus unique pair indexes. This keeps Drizzle's MySQL push flow stable while still preventing duplicate assignments.
- Money fields use TSH decimal columns instead of floats.
- Router secrets are named as encrypted fields; store encrypted values, not plaintext.
- JSON columns are used for flexible policy rules, package features, payment metadata, and package lists.
- Nullable foreign keys use `set null` when historical records should survive, while ownership-style records use `cascade`.
